# Viva Questions and Answers

## Basics
**1. What is supervised learning?**
The model learns from examples that include the correct answer (label). It then predicts the label for new inputs.

**2. Why is this regression and not classification?**
The target, power in kW, is a continuous number. Classification predicts categories.

**3. What are the features and the target?**
Features: irradiance, temperature, humidity, wind speed, cloud cover, hour. Target: `power_kw`.

**4. Is your dataset real?**
No. It is synthetic, generated from solar-geometry and panel-physics formulas plus noise. It is labelled as synthetic in the app, README and report. The pipeline can be retrained on real data with `--data`.

**5. Why use synthetic data?**
No single public dataset I could verify contained measured power plus all six features, and generating data makes the project reproducible offline. The trade-off is that scores do not show real-world accuracy.

## Data and preprocessing
**6. How did you handle missing values?**
Rows with no target are dropped. Missing feature values are imputed with the median inside the pipeline, fitted on training data only.

**7. Why impute inside the pipeline?**
If the median were computed on all data, test-set information would leak into training. In the pipeline, it is learned from the training split only.

**8. Why encode the hour as sine and cosine?**
Hour 23 and hour 0 are one hour apart, but as plain numbers they look far apart. Sine and cosine place hours on a circle.

**9. Why did you clip predictions at 0?**
Negative power is physically impossible; a linear model can output small negative values at night.

## Training and evaluation
**10. Why a chronological split instead of a random split?**
Neighbouring hours are very similar. A random split puts near-copies of test rows in training and gives over-optimistic scores. A chronological split mimics real use: train on the past, predict the future.

**11. What is data leakage?**
Information from outside the training data (for example, from the test set or the future) influencing training, making results look better than they really are.

**12. Explain MAE, MSE, RMSE and R².**
MAE: mean absolute error. MSE: mean squared error. RMSE: its square root, in kW. R²: fraction of variance explained; 1 is perfect and 0 equals predicting the mean.

**13. Why RMSE as well as MAE?**
RMSE penalises large errors more, which matters when big misses are costly.

**14. Why a baseline model?**
It gives R² a reference. A model that cannot beat "always predict the average" has learned nothing.

**15. What is cross-validation and why `TimeSeriesSplit`?**
Cross-validation repeatedly validates on held-out parts of the training data to choose hyper-parameters. `TimeSeriesSplit` always validates on data later than the training part, which respects time order.

**16. What did hyper-parameter tuning do?**
It tried small grids (for example tree depth, number of trees, learning rate) and picked the combination with the lowest cross-validated RMSE. The test set was not used for tuning.

**17. Your R² is about 0.99. Is that realistic?**
Not for a real plant. The target here is generated by a formula, so it is highly learnable. The result shows the pipeline works. Real data with noise, shading and sensor errors would score lower.

**18. Which model was best and can you be sure?**
The ranking is in the Model comparison page. The four non-linear models differ only slightly, so the order could change with another seed or data sample.

## Algorithms
**19. Why does Linear Regression perform worst?**
The relationship has non-linear parts (zero at night, efficiency effects, interaction between irradiance and hour), which a straight-line model cannot fit.

**20. Decision Tree vs Random Forest?**
A single tree is unstable and can overfit. A random forest averages many trees built on random samples, which reduces variance.

**21. Random Forest vs Extra Trees?**
Extra Trees chooses split thresholds at random, which makes it faster and adds more randomness.

**22. How does Gradient Boosting work?**
It adds small trees one by one, each trained to correct the errors of the ensemble so far.

**23. What is overfitting and how did you reduce it?**
Overfitting is memorising the training data and failing on new data. I limited tree depth and leaf size through tuning, averaged trees in ensembles, and evaluated on later, unseen data.

## Explanation
**24. What is feature importance?**
A score of how much each feature helps the model. Tree models give a built-in score from error reduction.

**25. Why also use permutation importance?**
It works for any model and is measured on test data. Built-in importance can be biased and is not available for Linear Regression.

**26. Why does cloud cover show low importance though clouds clearly reduce power?**
Cloud cover works through irradiance, which already contains the effect of clouds. When features are correlated, importance gets shared or hidden.

## System
**27. Why FastAPI and React?**
FastAPI serves the Python models over a REST API with automatic validation and documentation. React gives an interactive dashboard. The browser cannot run scikit-learn, so a backend is needed.

**28. How do you validate user input?**
The API checks that every feature is present and within its valid range (pydantic models and a service-level check) and returns a clear error otherwise. The app also warns about unlikely combinations, such as sunlight at night.

**29. Why save the whole pipeline with Joblib?**
So prediction applies exactly the same preprocessing as training; there is no chance of a mismatch.

**30. What are the limitations of the project?**
Synthetic data, one assumed plant, hourly resolution, user-supplied weather (no forecasting), and small hyper-parameter grids.

**31. How would you improve it?**
Use real measured data, add forecast weather and lag features, give probability ranges for predictions, and add plant capacity and panel tilt as inputs.

**32. How would you use your own dataset?**
Run `python train_model.py --data file.csv --source "..." --rename "old:new,..."`.
