# SolarPower AI

**Weather-Aware Solar Panel Power Output Prediction Using Supervised Machine Learning**
Category: Supervised Learning, Regression

A web application that predicts solar panel output (kW) from six weather inputs. Five regression
algorithms are trained, tuned and compared. The dashboard lets you predict, compare models, explore
the data, run what-if scenarios and see which weather factors matter.

> ### Dataset notice
> The bundled dataset is **synthetic** (generated by `backend/app/data_gen.py` from solar-geometry and
> panel-physics formulas plus noise). It is **not measured data**. Scores on it demonstrate that the
> pipeline works, not real-world accuracy. See "Using real data" below.

## Install and run on Windows

### Option 1: helper scripts
1. Double-click `setup.bat` (creates a virtual environment, installs packages, trains the models, runs `npm install`). Takes a few minutes.
2. Double-click `run.bat`. The browser opens at http://localhost:5173.

### Option 2: manual commands (Command Prompt)

```bat
cd solarpower-ai\backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python train_model.py
uvicorn app.main:app --port 8000
```

Open a **second** Command Prompt:

```bat
cd solarpower-ai\frontend
npm install
npm run dev
```

Open http://localhost:5173. The API documentation is at http://localhost:8000/docs.

macOS/Linux: same commands, with `source venv/bin/activate` instead of `venv\Scripts\activate`.

### Why are the trained models not included?
Joblib/pickle files only load reliably with the **same scikit-learn version** that created them.
Training takes a couple of minutes, so `train_model.py` creates models that match your installation.

## Using real data

1. Get a real dataset with measured power output and weather (for example a public solar plant dataset,
   or weather from NASA POWER / NREL joined with plant output). Check its licence and cite it.
2. It needs one row per time step, with a timestamp. Train with:

```bat
python train_model.py --data my_data.csv --source "Name and URL of your dataset" --rename "GHI:irradiance,T2M:temperature,Power:power_kw"
```

Required columns after renaming: `timestamp, irradiance, temperature, humidity, wind_speed, cloud_cover, power_kw`
(`hour` is derived from `timestamp` if missing). The dashboard banner then shows your source instead of the synthetic notice.
You can also upload a CSV of weather rows on the **Batch prediction** page to get predictions.

## ML workflow in brief

1. **Data**: synthetic generator (or your CSV) -> `data/solar_data.csv`.
2. **Cleaning**: sort by time, drop duplicate timestamps, mark impossible values as missing, drop rows with no target, clip negative power to 0.
3. **Feature engineering**: hour -> `hour_sin`, `hour_cos` (so 23:00 and 00:00 are neighbours).
4. **Missing values**: median imputation **inside** the pipeline, fitted only on training data (prevents leakage).
5. **Split**: chronological, oldest 80% train / newest 20% test. No shuffling.
6. **Models**: Linear Regression, Decision Tree, Random Forest, Extra Trees, Gradient Boosting, plus a mean-predicting baseline.
7. **Tuning**: small grid search with `TimeSeriesSplit` (3 folds) on training data only.
8. **Evaluation**: MAE, MSE, RMSE, R² on the untouched test set. Predictions are clipped at 0 kW.
9. **Explanation**: built-in tree importance and permutation importance.
10. **Saving**: each full pipeline (preprocessing + model) is saved with Joblib; metrics are saved to JSON and read by the dashboard. Nothing is hardcoded.

More detail is in `PROJECT_REPORT.md`.

## Troubleshooting

| Problem | Fix |
|---|---|
| Page says "Cannot reach the backend" | Start the backend (`uvicorn app.main:app --port 8000`) from the `backend` folder |
| "Trained models not found" | Run `python train_model.py` in `backend` |
| `uvicorn` not recognised | Activate the virtual environment first |
| Port already in use | Close the old window, or use another port (and update `vite.config.js`) |
